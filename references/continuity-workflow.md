# 15 秒分段一致性与连贯性工作流

本规范把长视频看成一串有状态交接的短片，而不是把一条长 Prompt 强行压缩给模型。不同平台的按钮和参数名称会变化，以下是从主流产品公开能力中抽象出的通用做法；实际使用时以目标平台当前版本为准。

## 市场上常见的四类方案

### 1. Video Extend / Continue

平台直接读取上一段视频并继续生成。优点是运动趋势、镜头惯性和环境变化较容易延续；缺点是人物脸部、服装细节、道具持有者和构图可能逐段漂移。它适合动作方向已经稳定的连续镜头，不适合作为唯一的一致性控制。

### 2. 首帧/尾帧图像条件

把上一段最后一个稳定画面作为下一段首帧参考，或同时指定当前段首尾帧。优点是能锁定人物位置、姿态、画面左右、道具状态和光线；缺点是不能完整传递运动速度和表演惯性。它是跨段一致性的硬锚点。

### 3. Character / scene / element reference

每段重复使用同一组角色图、场景图、道具图或元素参考。优点是身份和环境更稳定；缺点是只解决“长什么样”，不能解决“上一段动作结束在哪里”。因此必须与首帧/尾帧状态同时使用。

### 4. Seed / camera / control locking

在支持的平台中复用 seed、画幅、镜头运动、参考强度、摄像机控制或姿态控制。优点是减少随机变化；缺点是不同平台支持不一致，不能把它当作跨平台必备条件。

常见产品方向包括：Runway 的 Extend/参考工作流、Luma Dream Machine 的 Extend/首尾帧工作流、Kling 的元素与首尾帧类控制、Adobe Firefly 的首帧/尾帧和镜头控制、Google Veo 系列的参考图/续写能力，以及其他支持视频续写或图像条件的视频模型。具体功能会随版本、地区和套餐变化，生成前应核对目标平台当前界面。

## 本 Skill 采用的优先策略

一致性优先级：

1. 当前段首帧图或平台首帧条件；
2. 同一套角色、场景、道具参考资产；
3. 上一段视频的续写/运动参考；
4. 连续性合同文字；
5. 风格形容词和自由描述。

上一段视频不能替代尾帧图。视频参考负责运动趋势，尾帧图负责状态锁定；平台只支持一种输入时，优先尾帧图。

## 标准生产流程

### A. 生成全局资产

一次生成并固定角色、场景、道具、服装、伤势、色彩和光源参考图。每段沿用相同的 `<Subject N>` 和 `<Picture N>` 标签及其描述，不为同一资产重写同义描述。

### B. 建立连续性台账

台账至少记录：

- 角色身份、服装、发型、伤势和当前情绪；
- 场景锚点、画面左右、主动作轴线和摄影机所在侧；
- 每个道具的持有者、手、位置、可见性和状态；
- 当前动作的起点、终点、运动方向和速度；
- 主光方向、天气、环境底噪和配乐位置；
- 本段 `continuity_in` 和 `continuity_out`。

### C. 生成第一个单元

第一段从剧本初始构图开始，时长控制在 8—15 秒。结尾避免停在运动模糊、遮挡严重、人物变形或道具不可见的瞬间；尽量落在脚步落地、手已抓稳、人物停住或镜头稳定的状态。

### D. 提取尾帧

从上一段结尾选择最后一个稳定、清晰、可解释的画面作为下一段首帧图。通常优先检查结束前约 0.2—0.5 秒的画面，而不是机械使用最后一帧。尾帧应能看清主要角色、关键道具、画面左右、主光方向和背景锚点。

### E. 生成后续单元

下一段同时使用：

- 固定角色/场景/道具参考图；
- 上一段稳定尾帧图作为首帧锚点；
- 平台支持时，上一段视频作为运动参考或 Extend 输入；
- 当前段专属 H3 Prompt；
- `continuity_in` 中的状态复现句。

第一镜先复现尾帧，再开始新动作。不要在第一句就引入新的景别、服装、道具持有者或空间方向。

### F. 拼接与必要重叠

优先在稳定动作落点切段。对于打斗、奔跑和快速转身，可让下一段开头重复 0.3—1.0 秒的承接动作，生成后在剪辑中裁掉重复部分。重叠是编辑策略，不是允许单段超过 15 秒；每个生成文件仍必须不超过 15 秒。

## 失败时的诊断顺序

1. 人物或道具状态错：重新提取更清晰的尾帧，增强首帧条件。
2. 身份漂移：重新使用同一角色参考图和完全相同的主体定义，减少新形容词。
3. 运动方向反转：把动作方向和摄影机侧写入 `continuity_in`，并缩短单段时长。
4. 场景跳变：加入固定锚点和主光方向，避免下一段重新生成建立镜头。
5. 台词或声音断裂：把对白完整放在一个单元内；将连续环境声和配乐放在后期统一处理。
6. 多人打斗混乱：降低每段复杂动作数量，先锁定首帧站位，再生成一个主要动作链；必要时改为正反打或分角色镜头。

## Skill 的交付要求

每个分段 Prompt 前必须提供 `continuity_in`、`continuity_out` 和 `generation_inputs`。六字段代码块内部只保留官方字段，不嵌入自定义的连续性字段。除非用户另有要求，Skill 不输出覆盖全片的长 Prompt。
