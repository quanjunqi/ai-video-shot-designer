# 跨批次台账与素材命名规范

分段 + 批次化交付意味着一致性状态要跨多轮、甚至跨会话保持。本规范定义一份随批次滚动更新的**项目台账**、每批次的协作回传清单，以及确定性的素材文件命名。台账属于规划/生成设置，**不嵌入 H3 六字段**。

## 1. 项目台账（纯文本，随批次滚动更新）

新项目首次交付时建立，之后每批更新一次：

```text
项目台账：<片名>
目标模型/版本核对日期：<对应 platform-spec §0 的核对日期>
画幅 / 风格 / 总时长估算 / 预计单元数：

标签编号表（一经分配不再改写）：
- Subject 1 = <角色/场景/道具名>：<一套固定外观描述>
- Subject 2 = ...
- Picture N = <所属单元与构图用途>
- Video N / Audio N = <仅当用户明确提供，记录来源>

资产清单（标签 → 已生成素材文件名 → 覆盖视图）：
- Subject 1 → sub01_<名>_sheet.png（正面/45度/特写）

单元滚动表：
- 单元 N ｜ 全片时间线 ｜ 本段时间线 ｜ continuity_out 摘要 ｜ 尾帧文件 ｜ 尾部视频(可选) ｜ 状态(待生成/已生成/用户已确认)
```

## 2. 每批次协作循环

1. 助手按 platform-spec §2 交付当前批次（资产/故事板 Prompt ＋ 1—3 个分段 H3 Prompt）。
2. 用户在平台生成后回传三样东西：
   - 每个单元**实际选定的尾帧图**（按 §3 命名）；
   - 可选的单元尾部视频（用于运动参考，不替代尾帧）；
   - 漂移/问题反馈（身份、方向、光线、台词等）。
3. 助手把回传尾帧状态写入台账单元滚动表，作为下一单元 `continuity_in`，并按 [continuity-workflow.md](continuity-workflow.md) 的诊断顺序处理反馈，再交付下一批。
4. 用户确认上一批前不展开后续批次；用户明确要求“全部生成单元”时才一次性展开。

## 3. 素材文件命名约定（可排序、跨平台）

- 编号两位零填充、全小写、下划线分词，文件名不用空格与中文（避免跨平台问题），标签号与文件名一一对应。
- 角色资产：`sub01_<name>_sheet.png`、`sub01_<name>_face.png`
- 场景资产：`scn01_<name>_empty.png`；道具：`prop01_<name>.png`
- 故事板：`pic02_<unit-or-action>.png`
- 单元成片：`u03_gen.mp4`；单元实际尾帧：`u03_tailframe.png`（截取的具体时间点记入台账）
- 批次目录：`batch02_u04-u06/`

示例：单元 2 的交接尾帧命名为 `u02_tailframe.png`，台账记录“00:23.6 截取，信封已在林岚双手、陈默右手空、主光 camera-right”，单元 3 的连续性输入直接引用该状态与文件。

## 4. 跨会话恢复

新开会话或上下文丢失时，请用户提供：项目台账文件 ＋ 最近一个已确认单元的实际尾帧图（必要时加尾部视频）。助手据此重建标签表与连续性状态，不凭印象猜测编号、外观或上一段落点；恢复后先用一两句向用户复述最近单元的 continuity_out 再继续。

## 5. 边界

台账、命名与回传清单只用于选素材、配置平台和后期剪辑；进入模型的只有按 [output-schema.md](output-schema.md) 组织的六字段 Prompt 与块前中文生成设置，台账内容不写进六字段。
