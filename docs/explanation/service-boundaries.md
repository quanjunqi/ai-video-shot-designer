# 为什么是 6 个微服务？

每个服务拥有一类独立数据，变更节奏和扩容需求不同。

## 服务分工

| 服务 | 管什么 | 为什么独立 |
|---|---|---|
| workspace | 用户、授权、渠道凭据 | 安全敏感，密钥加密，和业务数据变更节奏不同 |
| production | 项目、分镜、模型目录 | 业务核心，读写频繁，不执行 AI 调用 |
| execution | 任务调度、AI 网关、审计 | 计算密集，需要 worker 池和限流 |
| asset | 文件上传、媒体处理 | IO 密集，大文件和缩略图 |
| web-bff | 前端入口，转发请求 | 无状态，薄聚合层 |
| outbox-relay | 事件消息投递 | 基础设施，和业务解耦 |

## 好处

- 独立部署：前端改了不用重启 AI 网关
- 独立扩容：execution 可以按调用量单独扩
- 故障隔离：一个服务挂了不影响其他
- 安全边界：密钥只在 workspace，其他服务拿不到明文
