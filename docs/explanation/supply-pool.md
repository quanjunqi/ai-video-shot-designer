# 什么是「供给池」？

> 中转站 API 的多渠道失败切换机制。见 ADR-004。

## 问题

同一个模型（比如 GPT-4o）可能通过多个渠道访问：
- 官方 OpenAI API
- 中转站 A（便宜但慢）
- 中转站 B（快但贵）

用户提交一个任务，到底走哪个渠道？

## 供给池方案

1. **目录定义**：production 服务里维护"逻辑模型" → 多个"物理渠道"的映射
2. **运行时锁定**：execution 提交任务时锁定一个渠道快照
3. **失败切换**：当前渠道失败时，自动尝试供给池里的下一个渠道
4. **成本优先**：优先选最便宜的可用渠道

## 为什么叫"池"？

因为它像资源池——一组可替换的供给源，任务从池里拿一个用，坏了换一个。
不是写死一个渠道地址，而是维护一个优先级列表。

## 和"路由层"的区别

- **路由层**（ADR-003）：决定用哪个模型
- **供给池**（ADR-004）：同一个模型，走哪个渠道

两层是正交的：先选模型，再选渠道。
