设计说明（供评审）

  1. 挂载位置：成本中心下新增「健康」标签页（与 ModelAudit/ModelCosts 同级），路由 /settings/health 或成本中心 tab。
  2. 数据源：新增 execution 聚合端点 /internal/v1/audit/health（按单元聚合错误码分布 + 成功率，复用 T2-1 的 audit 表查询模式），叠加 channel_health 表的熔断状态（正常/冷却/半开）与最近失败/成功时间。BFF 加代理端点 /api/v1/audit/health。
  3. 熔断三态判定：cooldown_until IS NULL → 正常；cooldown_until > now → 冷却中（显示剩余秒数）；cooldown_until <= now 且 probe_owner 非空 → 半开探活；无 channel_health 行 → 正常（fail-open 语义一致）。
  4. 错误码分布：按 breaker.Classify 分类着色——成功(绿)/硬4xx(红)/软4xx(琥珀)/5xx(橙)/网络(蓝)/内容安全(紫)。无数据单元显示「—」。
  5. 告警（三类最小）：①错误率突增：滚动窗口错误率 > 阈值(默认20%,可配)持续 5 分钟 → webhook；②熔断发生：单元进入冷却 → webhook（去重，同一单元冷却期间只发一次）；③同步失败：渠道同步任务失败 → webhook。webhook 简单 POST + 3 次重试，无独立告警服务（P1 外）。
  6. 告警配置 UI：面板底部折叠区（默认展开），阈值/开关/webhook URL 可编辑，存 workspace 配置（复用 budget_rules 的 workspace 配置模式）。
  7. 待定：告警配置存哪（workspace 新表 vs execution 配置表）？面板路由放哪（独立页 vs 成本中心 tab）？请在评审中确认。
