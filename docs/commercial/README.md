# 镜序 Studio：AIGC 创作与生产平台

版本：1.0（立项方案）  
日期：2026-09-19

## 1. 立项定义

镜序 Studio 是建立在统一模型与算力底座上的包容型 AIGC 创作平台。产品不按用户是否“专业”或“高级”划分入口，而按用户当前要完成的任务提供不同创作方式：

```text
快速创作：直接生成一组图片或一段/多段视频
工作流编排：把多个生成步骤组织成可重复执行的流程
漫剧工作台：完成剧本、资产、分镜、生成、审核和交付
社区与方法：作品、工作流和经验的发布与 Remix
```

快速创作、工作流和漫剧不是用户等级，也不是互斥套餐。同一个用户可以在一次创作中自由流转。工作流是领域模型，“无限画布”只是候选交互之一；默认应优先提供易读的步骤式编排，必要时再切换画布查看分支和依赖。

漫剧是第一个专业工作台，但不是平台边界。平台首先必须解决的不是增加更多页面，而是让同一个模型能力能够可靠运行在三种执行线路上：

1. **API 调用**：官方 API 或合规聚合服务；
2. **本地 ComfyUI**：用户设备上的 ComfyUI，由安全的 Local Agent 接入；
3. **云端算力**：平台托管或用户自有 GPU，通过标准 Runner 运行 ComfyUI/推理容器。

三个线路共享能力模型、输入输出契约、任务状态、资产、费用和观测体系。创作工作台只依赖统一 Capability，不直接依赖某个 Provider 或 ComfyUI 节点。

## 2. 当前范围边界

本阶段明确不接入 `/Users/quanjunqi/depth-video-converter` 的任何代码或能力，也不把深度、姿态、视频切片和音频分离列为 MVP 依赖。后续是否作为独立插件评估，不影响当前平台架构。

当前四个核心建设域：

| 建设域 | 目标 |
|---|---|
| 模型能力中心 | 统一模型、版本、能力、Schema、Adapter 和兼容规则 |

| 创作与生产空间 | 图片/视频快速生成、工作流编排、漫剧工作台共享底座 |
| 商业与治理 | 租户、权限、任务、资产、计量、账单、审计和社区发布 |

## 4. 核心产品原则

1. **能力优先于模型名称**：用户选择“文生视频/图生视频”，系统再匹配模型和线路。
2. **控制面与数据面分离**：项目、任务、计费和策略在控制面；真实推理在 API、Local Agent 或 Cloud Runner 中执行。
3. **工作流与执行解耦**：WorkflowVersion 固定业务步骤，ExecutionPlan 决定本次运行线路。
4. **资产不可变、结果可追溯**：所有输入输出绑定版本、哈希、模型、参数和 Run。
5. **任务成功不等于内容通过**：系统执行状态和创意审核状态分开。
6. **专业规则不退化为通用 DAG**：漫剧继续保留 Shot / Unit / Take、Gate、审核和连续性。
7. **Agent 只能调用受控工具**：不能绕过权限、预算、版本和发布审核。
8. **先做工程底座再扩模型数量**：可靠执行、观测、成本和安全是接入新模型的前提。

## 5. 立项后的首个目标

第一个可商用版本需要完成三条黄金路径：

- 个人创作者用同一模板在 API、本地 ComfyUI 或云 GPU 中任选可用线路并得到结果；
- 漫剧团队完成从剧本到 adopted Take 的专业生产闭环；
- 工作流作者发布不含密钥和私有资产的版本快照，其他用户能完成 Remix。

## 6. 立项 Gate

进入封闭 Beta 前必须满足：

- 三类执行线路至少各有一条可运行实现；
- Worker/Agent 中断后任务可恢复或安全终止，不重复计费；
- 模型、工作流、资产、任务和费用全链路可追溯；
- 组织、项目、Secret 和对象存储通过越权测试；
- 本地 ComfyUI 通过出站连接接入，不要求用户暴露公网端口；
- 云端 GPU 支持容量、租约、心跳、闲置回收和成本上限；
- 漫剧领域 Runtime 的 110 项基线测试持续通过；
- 社区发布完成依赖冻结、敏感字段过滤和来源归因。

## 7. 立项结论

建议正式立项，采用“基础设施先行、创作空间并行验证”的节奏。模型与算力平台是所有工作台的共同生产资料，应该作为第一阶段主干建设；漫剧则作为验证这套底座能否支撑复杂专业生产的首个标杆场景。
