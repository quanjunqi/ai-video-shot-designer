# 可行性与差距分析

## 1. 结论

项目可以立项。核心技术路径清晰，但需要按平台工程重新建设，不能把现有项目简单拼接后直接商业化。

| 维度 | 判断 | 说明 |
|---|---|---|
| 快速图片/视频生成 | 高 | 现有前后端已有模型表单和生成调用基础 |
| API 模型接入 | 中高 | Provider 基础存在，需标准化 Adapter、用量和可靠任务 |
| 本地 ComfyUI | 中 | 技术成熟，但需新建安全 Local Agent 和依赖治理 |
| 云端算力 | 中 | 可实现，主要难点是 GPU 调度、镜像、缓存和成本控制 |
| 工作流 | 中高 | 已有 DAG 基础，需从“画布功能”升级为多视图执行产品 |
| 漫剧专业工作台 | 高 | Shot Designer 领域规则和测试基线较完整 |
| 商业 SaaS 成熟度 | 低 | 租户、权限、Secret、计费、审计和 SRE 尚未补齐 |

技术上没有不可解决的阻碍。真正风险是范围过大、底层协议不统一、过早建设复杂画布，以及云 GPU 单位经济没有验证。

## 2. 当前范围

本次可行性只评估：

- 图片/视频快速生成；
- 工作流定义与执行；
- 漫剧工作台；
- API、本地 ComfyUI、云端算力；
- 项目、资产、任务、计量、计费、社区和治理。

`/Users/quanjunqi/depth-video-converter` 明确不接入、不迁移、不作为依赖，也不纳入本期成本和工期。

## 3. 现有项目复用

### 3.1 `ai-worker`

可复用：

- Go + Gin、PostgreSQL、MinIO/OSS；
- 模型、厂商、来源和能力元数据；
- 图像/视频生成调用和状态查询；
- SSE、工具白名单、模板和通用 DAG 基础；
- 素材和生成历史的早期数据结构。

必须重构：

- 进程内 goroutine 长任务；
- Provider 与业务接口耦合；
- 缺少 Workspace Scope、RBAC 和项目隔离；
- 缺少 ModelVersion、AdapterVersion、Deployment 和 Route；
- 缺少 Quote、Reservation、Usage、Ledger；
- Secret 回显、明文配置和宽 CORS 风险；
- 缺少服务契约和自动化测试。

判断：可作为实现参考和迁移来源，不应把当前单体直接当作目标微服务架构。

### 3.2 `ai-worker-frontend`

可复用：

- Vue 3、Vite、Pinia、Vue Router；
- 图片/视频参数控件；
- 模型能力驱动表单；
- 资产、任务、模板和 Vue Flow 组件；
- 进度和结果预览。

必须重构：

- 从工具导航改为图片、视频、工作流、漫剧的任务导航；
- 快速生成默认只保留高频参数；
- DAG 编辑器不再等同于工作流产品；
- 增加步骤视图、批量视图和模板简化表单；
- 新建模型能力、Local ComfyUI、云算力、成本和治理界面；
- 拆分大型组件并建立状态与 E2E 测试。

判断：前端技术栈可保留，产品 Shell 和状态模型需要重建。

### 3.3 `ai-video-shot-designer`

可复用：

- 剧本锁、阶段 Gate 和覆盖校验；
- Canonical Asset、Scene Map、走位和机位；
- Shot Card、Unit Plan 和连续性账本；
- 产物版本、审核绑定和依赖失效；
- Adapter/Prompt 校验和实际尾帧；
- 当前 110 项回归测试。

产品化差距：

- 文件/CLI 形态需要服务化；
- 需要数据库事务、并发和多用户审核；
- 需要与统一 Asset、Job 和 Billing 对接；
- Runtime/Schema/Config 必须版本固定。

判断：专业工作台的核心领域资产，应封装为独立 Runtime，不能在通用工作流或 Go 服务中重新实现一遍。

## 4. API 路线可行性

### 已有基础

现有 Provider 模型可以扩展为 Connector；图片/视频异步调用模式已经存在。

### 必要建设

- Capability Schema 和统一错误模型；
- ModelVersion、AdapterVersion 和价格版本；
- Secret Vault 和只写配置；
- Webhook 签名、轮询降级和幂等；
- 限流、熔断、健康和 Provider 隔离；
- 实际 Usage 与账本对账；
- Provider sandbox/fixture 契约测试。

### 风险

- 供应商参数语义不同，统一 Schema 不能变成最低公分母；
- 视频 API 长任务可能数分钟，必须持久化恢复；
- 供应商任务幂等能力不一致，重试可能重复扣费；
- 模型和价格会变化，运行必须锁定版本快照。

结论：技术可行，是第一条应完成的执行线路。

## 5. 本地 ComfyUI 可行性

### 推荐方案

开发跨平台 Local Agent。Agent 主动通过 mTLS WebSocket/gRPC 连接平台，访问本机 ComfyUI HTTP/WebSocket API。平台不直接访问用户局域网。

### Agent 职责

- 配对和设备身份；
- ComfyUI、GPU、模型和自定义节点探测；
- Workflow JSON 参数注入；
- 输入素材的受控下载或本地映射；
- Prompt 提交、进度、取消和结果校验；
- 断线恢复和版本升级；
- 输出上传策略和本地文件权限。

### 主要难点

- Windows/macOS/Linux 环境差异；
- 自定义节点依赖和任意代码风险；
- 模型命名、目录和版本不一致；
- 本地磁盘、显存和 ComfyUI 队列不足；
- Agent 离线后的租约与任务恢复；
- 大文件传输和隐私策略。

### 缓解

- 首版只支持签名/允许列表 Workflow 和节点；
- 提供依赖 Preflight，不自动执行未知安装脚本；
- 用模型 Manifest + 哈希识别，不依赖文件名；
- Agent 报告资源并拒绝超限任务；
- 使用 prompt id 恢复，不盲目重提；
- 允许“输入不上传、输出可选上传”的本地模式。

结论：技术可行，是产品包容性和低成本能力的重要组成，但需要独立工程投入，不能等同于浏览器直接连 ComfyUI。

## 6. 云端算力可行性

### 推荐方案

使用 Kubernetes GPU NodePool + 标准 Runner 镜像。Cloud Runner Controller 管理热实例、短生命周期实例、模型缓存和任务租约。外部云（包括 AutoDL 类资源）通过 Cloud Compute Adapter 接入同一 Fleet 模型。

### 必要能力

- GPU 型号、显存和区域资源目录；
- Runner/镜像/工作流/模型版本；
- 容量预留、队列、优先级和并发；
- 模型缓存、共享只读卷或对象缓存；
- 实例启动、健康、隔离和闲置回收；
- GPU 秒、实例分钟、存储和带宽计量；
- 成本上限、预算告警和失败补偿。

### 主要难点

- 模型下载导致冷启动过长；
- GPU 型号与工作流需求不匹配；
- ComfyUI 自定义节点供应链风险；
- 空闲实例产生不可见成本；
- Spot/抢占实例导致任务中断；
- 云账户和区域差异。

### 缓解

- 热池 + 分层模型缓存；
- Workflow 声明 VRAM/磁盘/节点依赖；
- 镜像签名、SBOM 和允许列表；
- Lease/Heartbeat + checkpoint 能力分类；
- 空闲 TTL 和费用硬上限；
- Cloud Adapter 屏蔽各供应商实例 API 差异。

结论：可行，但云 GPU 是最大成本和运维风险，应在 API 路线稳定后建设，并以真实工作负载验证容量模型。

## 7. 工作流可行性

底层 DAG、层内并行和 Vue Flow 已有基础。真正缺口不是画布组件，而是：

- WorkflowDraft/Version/Run/Job 的清晰模型；
- 长流程恢复、人工等待和补偿；
- 输入输出 Schema、变量和批量矩阵；
- 多视图编辑同一结构；
- 单步运行、缓存和局部重试；
- 费用预测和执行线路锁定。

推荐 Temporal 作为长流程编排，Vue Flow 仅作为画布视图。步骤和批量视图通过同一 Workflow API 操作。

风险是同时研发三种编辑器导致周期膨胀。建议先交付步骤视图和模板运行，再用用户研究决定画布功能深度。

## 8. 微服务可行性

采用逻辑微服务边界、渐进物理拆分。首期 9 个部署单元可由现有团队维护；执行端独立以隔离故障和安全风险。

必须引入的基础设施：

- PostgreSQL；
- Temporal；
- Kafka/Redpanda；
- S3/MinIO；
- Redis；
- Vault/KMS；
- OpenTelemetry；
- Kubernetes（云 Runner 必需）。

这比当前单体复杂，代价是合理的，因为执行任务跨分钟/小时、线路异构、费用敏感且需要恢复。仍应避免在首期把低流量服务全部物理拆散。

## 9. 商业与安全风险

### P0：现有 Secret

`ai-worker/config.yaml` 中存在明文凭据和疑似真实 OSS Key。必须立即轮换、移除、扫描 Git 历史并改用 Secret Store。

### P0：多租户隔离

当前项目缺少完整 Workspace Scope。必须从 API、Repository、事件、对象存储和搜索五层强制隔离。

### P0：任务和计费

进程内长任务不能满足商业要求。Job、Attempt、幂等、租约、Usage 去重和不可变账本必须先完成。

### P1：ComfyUI 供应链

自定义节点可以运行任意代码。平台托管 Runner 只能运行签名镜像和允许列表；本地 Agent 必须明确展示风险，不能远程静默安装未知节点。

### P1：云 GPU 毛利

需要持续测量有效结果成本、冷启动、缓存命中和闲置成本。不能只根据 GPU 每小时价格定价。

### P1：工作流交互假设

画布可能不是多数用户的主要需求。必须通过任务测试验证步骤、批量、表单和画布的真实占比，避免把研发资源投入低频交互。

### P1：模型许可证与服务条款

每个模型、权重、ComfyUI 节点和 Provider 都需要代码、权重、商业托管、输出和数据处理条款记录。未核验组件默认不能进入公共收费线路。

## 11. Go / No-Go Gate

### 基础设施 Gate

- API、本地 ComfyUI、云 GPU 各完成至少一个标准 Capability；
- 相同 WorkflowVersion 可在至少两条线路运行；
- 中断、重试和重复事件不产生重复扣费；
- Asset、Usage、Ledger 和 Trace 可完整核对；
- Local Agent 不需要公网入站端口；
- GPU 实例可自动回收并核算闲置成本。

### 产品 Gate

- 图片和视频快速生成无需理解工作流即可完成；
- 用户可用步骤视图建立并第二次运行工作流；
- 画布是否进入主入口由可用性数据决定；
- 2-3 个团队用漫剧工作台独立完成一集；
- 社区 Remix 在依赖缺失时给出明确处理。

### 商业 Gate

- 真实价格下仍有持续使用；
- 三类线路的有效结果成本可比较；
- 至少一个用户群愿意为订阅/协作/托管算力付费；
- 权限、Secret、备份、删除和审计演练通过；
- 模型与节点许可证清单完整。

## 12. 最终判断

立项可行，但架构主线必须从“做更多创作页面”调整为“先建立统一模型与算力协议”。快速生成用于验证底座易用性，工作流用于验证复用与批量，漫剧用于验证复杂生产。三者共同验证平台，而不是三个彼此割裂的产品。
