# 商业化路线与单位经济

## 1. 商业化逻辑

平台的收入不能只依赖模型 API 差价。长期价值来自四部分：

- 统一模型与算力带来的稳定执行和成本选择；
- 工作流的复用、批量和团队效率；
- 漫剧专业生产降低返工和协作成本；
- 社区方法带来的分发、Remix 和生态供给。

快速创作、工作流和漫剧不是三个用户等级。套餐差异应来自资源额度、协作、治理、托管服务和 SLA。

## 2. 套餐假设

| 套餐 | 主要权益 | 收费方式 |
|---|---|---|
| Free | 有限项目/资产、自带 API、本地 ComfyUI、社区 | 免费 |
| Pro | 更多项目、工作流、批量运行、平台模型和云算力 | 订阅 + 用量 |
| Team | 成员、漫剧、审核、预算、审计和共享资产 | 席位 + 用量 |
| Enterprise | SSO、私有化、专属集群、专属 Adapter 和 SLA | 年度合同 |

正式价格在真实试点后确定。不能用不透明积分掩盖供应商成本，但可在用户侧使用统一钱包简化支付。

## 3. 单位经济

```text
任务成本 = API 成本 + GPU 秒 + 存储/带宽 + 失败重试 + 运营分摊
有效结果成本 = 全部任务成本 / 被下载、发布或采纳的结果数
云算力毛利 = 云任务收入 - 实例运行 - 闲置 - 模型分发 - 网络成本
项目贡献毛利 = 订阅分摊 + 用量收入 - 真实可变成本
```

本地 ComfyUI 任务不产生平台 GPU 成本，但仍产生存储、同步、编排和支持成本。自带 API 也不是免费产品，价值通过订阅、工作流和治理收取。

## 4. 三类线路商业策略

### API

- 优点：启动快、无需容量投资；
- 收入：用量加价或订阅内服务费；
- 控制：价格版本、失败退款、供应商对账；
- 风险：毛利受供应商影响。

### 本地 ComfyUI

- 优点：用户已有硬件和模型，平台边际算力成本低；
- 收入：Pro 功能、工作流、设备管理、团队协作；
- 控制：Agent 版本、允许节点、支持范围；
- 风险：环境碎片化导致支持成本过高。

### 云端算力

- 优点：可提供完整模型自由度和批量生产；
- 收入：GPU 分钟、任务套餐或专属容量；
- 控制：热池、模型缓存、实例回收和预算；
- 风险：冷启动与闲置吞噬毛利。

## 5. 低成本策略

1. 输入与依赖 Preflight，避免必然失败；
2. 预览质量先行，再运行高质量版本；
3. 固定模型/Seed 的确定性步骤按内容哈希缓存；
4. 用户已有本地模型时优先 Local ComfyUI；
5. 批量任务集中到预热的云 GPU；
6. 根据模型缓存、队列和成功率调度；
7. 失败任务按错误类型重试，不盲目重提；
8. 用有效结果成本和 Take 采纳率优化，而不是只看生成成功率。

## 6. 里程碑

### Phase 0：工程与安全基线（第 1-3 周）

- Secret 轮换、认证、Workspace、RBAC 和审计；
- 服务模板、CI、契约和本地开发环境；
- Job、Asset、Capability、Usage v1；
- 现有项目迁移边界和测试基线。

退出：无已知 P0 Secret/越权；任务与账本不变量有自动测试。

### Phase 1：API + 快速创作（第 4-8 周）

- 图片/视频快速生成；
- Capability、Model、Adapter、Provider；
- Quote、Job、Asset 和 Usage 闭环；
- 两个 API Provider；
- 任务中心和用量中心。

退出：20 位种子用户能独立生成并回到历史结果；费用可对账。

### Phase 2：Local ComfyUI + 工作流步骤（第 9-13 周）

- Local Agent 配对和设备管理；
- ComfyUI Workflow Adapter、依赖预检和断线恢复；
- 工作流步骤视图、版本、单步运行；
- 模板简化表单。

退出：同一能力可在 API 和本地运行；10 位用户第二次运行自己保存的工作流。

### Phase 3：Cloud Compute + 批量（第 14-19 周）

- Cloud Fleet、Runner Controller 和受控 GPU 池；
- 镜像/模型缓存、调度和闲置回收；
- 批量视图、变量矩阵和局部重试；
- 三条线路的成本和质量对比。

退出：云 GPU 利用率和有效结果成本达到试点目标；故障可降级。

### Phase 4：漫剧 Closed Beta（第 16-24 周，可并行）

- Shot Designer Runtime；
- 剧本、资产、空间、Shot / Unit / Take；
- 审核、stale、连续性、预算和交付；
- 画布视图根据前期验证决定投入深度。

退出：2-3 个团队不依赖开发者改库完成一集；第二集仍愿意使用。

### Phase 5：社区与商业 Beta（第 25-28 周）

- Publication Snapshot、依赖预检和 DLP；
- 作品/工作流发布、收藏、举报和 Remix；
- 支付、套餐、配额和运营后台；
- 灾备、安全、容量和财务对账演练。

## 7. 产品验证

### 快速创作

- 首次图片结果时间；
- 首次视频结果时间；
- 生成后继续变体、下载或加入项目的比例；
- 用户是否理解模型与线路的区别。

### 工作流

- 首次建立工作流完成率；
- 第二次运行率；
- 步骤、批量、画布、简化表单的任务完成时间；
- 画布是否只在排错时有价值；
- 发布模板后的 Remix 成功率。

### 漫剧

- 每个 adopted Unit 成本；
- Take 采纳率；
- 一致性驳回率；
- 上游变更的局部返工范围；
- 团队第二集留存和付费意愿。

### 模型与算力

- 三类线路成功率和 P95 完成时间；
- API 价格偏差和重试成本；
- Local Agent 配对/在线/恢复率；
- 云 GPU 冷启动、利用率、缓存命中和闲置率；
- 自动路由被用户手动改选的比例。

## 8. 试点设计

- 20 位创作者：完成图片、视频和至少一个两次运行的工作流；
- 10 位 ComfyUI 用户：覆盖 Windows、macOS 和不同 GPU；
- 5 位批量创作者：验证步骤、表格和画布的真实需求；
- 2-3 个漫剧团队：各完成至少一集；
- 5 位方法作者：发布后由陌生用户 Remix。

所有试点使用真实任务和接近真实价格，避免补贴掩盖价值。

## 9. Go / Pivot / Stop

### Go

- 快速生成形成稳定周使用；
- 工作流第二次运行和批量复用成立；
- API、本地、云三类线路至少两类有稳定使用；
- 漫剧团队完成第二个项目；
- 单位经济、安全和任务可靠性达标。

### Pivot

- 步骤视图高频、画布低频：把画布降为排错工具；
- 本地 ComfyUI 高使用：强化 Agent/工作流订阅，减少自营 GPU；
- 云算力毛利不成立：转为用户自有云和 API 聚合；
- 漫剧价值显著高于通用创作：加强 Team 销售而不取消通用底座；
- 社区发布弱但私有模板强：先做团队方法库。

### Stop / 暂停扩张

- 正常价格下用户不持续生成；
- 工作流第二次运行率长期过低；
- 云 GPU 闲置和失败成本无法控制；
- Local Agent 支持成本高于订阅价值；
- P0 隔离、Secret、计费或许可证问题未解决。

## 10. 商业化结论

首个商业验证重点不是社区规模或模型数量，而是：用户能否以可理解的方式选择三类线路，能否把一次生成沉淀为可重复方法，漫剧团队是否因专业生产链减少返工。基础设施完成后，社区和更多专业工作台才有可持续扩张条件。
