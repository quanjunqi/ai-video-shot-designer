# 完整产品原型说明

## 1. 原型范围

本原型验证“一个共享平台、三种创作入口”的产品结构，而不是最终品牌视觉。交互原型包含七个可切换核心空间：

1. 创作首页；
2. 快速创作台；
3. 自由工作流 Canvas；
4. 漫剧专业工作台；
5. 作品与方法社区；
6. 模型与执行线路；
7. 热门视频实验复盘。

## 2. 全局应用框架

顶部提供统一搜索、任务、通知和账户；左侧导航把工作区与生产管理分开。无论用户从快速创作、Canvas、漫剧还是社区 Remix 进入，都使用同一套项目、资产、任务和算力身份。

桌面端左侧导航常驻；中等宽度折叠为图标栏；移动端只保留高频入口。真实产品的专业生产主要面向桌面，移动端 MVP 以查看任务、审核和社区为主，不强求完成复杂 Canvas 编辑。

## 3. 创作首页

首页不展示模型列表，而是以“创作目标”作为第一输入：

- 自然语言描述任务，可添加视频或选择模板；
- 三个入口分别对应快速创作、自由工作流和漫剧专业工作台；
- 右侧显示运行任务、用量、本地节省和待审核；
- 下方继续最近项目，并直接暴露状态和阻塞。

关键验证：新用户是否理解三种入口差异；老用户能否立即回到未完成工作。

## 4. 快速创作台

原型展示“确认生成计划”状态：

- 用户只填写内容类型、成片规格和创作要求；
- 系统生成音频分离、切片、开场版本和导出计划；
- 线路面板对比低成本、快速和隐私优先方案；
- 执行前展示时间、费用区间和缓存复用；
- 高级用户可把计划展开为 Canvas。

关键验证：用户能否在不理解节点或 Provider 的情况下作出线路与预算决定。

## 5. 漫剧专业工作台

原型保留专业生产的三栏结构：

- 左侧是领域阶段和审核入口；
- 中间是 Scene、Shot、Unit、导演事实、连续性和 Takes；
- 右侧是 Director Agent、校验、费用和正式动作。

界面同时展示“任务成功”和“创意待审核”，避免用户误把生成完成当作正式通过。用户选择 Take 后，可以执行“采纳并继续”，此操作解锁下一 Unit。

必须保留的概念：

```text
Shot = 导演事实
Unit = 模型执行单元
Take = 一次实际结果
```

关键验证：导演是否理解 Shot 不等于 Unit；审核人能否找到连续性风险；采纳动作是否足够明确。

## 6. 社区与 Remix

每个社区条目同时展示成品和复现信息：预计成本、节点数量、专业要求、Remix 数和可复现状态。社区页还明确展示发布快照的三个部分：

- 工作流版本；
- 模型、线路、素材与成本依赖；
- 来源归因和独立 Remix。

真实发布流程需要独立的 Preflight 页面，逐项展示：公开媒体、参数、隐藏字段、许可证、预计成本、可替代依赖和内容安全结果。不能用一个“我已阅读”复选框代替检查。

关键验证：用户点击 Remix 前是否理解成本和缺失依赖；作者是否愿意分享可复现方法，而不只是视频。

## 7. 模型与算力

原型将线路按运行方式展示：官方/聚合 API、用户 AutoDL、本地 Runner、浏览器 WebGPU 和平台 Media GPU。用户可选择智能平衡、最低成本和隐私优先策略，并看到平台与本地用量。

真实产品还应支持：

- 以 Capability 筛选，不让用户先选择供应商；
- 线路健康、队列、冷启动和地区；
- Provider 价格版本和许可证范围；
- 密钥只写、Runner 配对和 AutoDL 闲置关机；
- 项目级允许线路和预算策略。

## 8. Canvas 补充页面规格

本轮可交互原型已呈现 Canvas 的节点库、画布、节点参数与单节点运行状态；工程实现继续遵循以下布局：

```text
左：节点库与搜索
中：画布、节点和连线
右：所选节点的输入、参数、线路、费用和输出
下：运行日志、任务时间线和错误详情（按需展开）
```

Canvas 顶部只保留版本、运行、发布模板和提交到专业项目。节点状态区分未准备、就绪、运行、成功、失败和 stale。单节点运行不能在无提示时绕过上游版本变化。

## 9. 发布 Preflight 补充页面规格

发布向导分四步：

1. 选择作品版本和封面；
2. 选择是否公开 Workflow、Prompt、参数和素材；
3. 检查依赖、许可证、成本、替代线路和敏感信息；
4. 设置标题、说明、分类、许可和署名后提交审核。

发布后生成不可变 Publication Snapshot。用户修改项目或方法时只能发布新版本，不能静默改变旧快照。

## 10. 实验复盘补充页面规格

实验页采用同一基线下的 Variant 表格和结果对比：

- 自变量：开场、封面、脚本、Prompt、模型、时长；
- 控制条件：平台、账号、发布时间、投放；
- 指标：播放、3 秒留存、完播、互动、转化；
- 输出：差异摘要、数据不足提示、保存为方法。

界面不提供“爆款分数”。数据不足或外部条件不可比时必须明确标记。

## 11. 原型评审脚本

建议用 45-60 分钟完成一次评审：

1. 让新用户从首页创建“访谈三版开场”，观察是否能独立完成线路选择；
2. 让高级用户说明何时会展开为 Canvas；
3. 让导演在漫剧生产台指出任务状态、创意状态和下一 Unit 阻塞；
4. 让审核人选择并采纳一个 Take；
5. 让创作者在社区判断某个方法是否可复现、成本是否可接受；
6. 让用户选择本地、AutoDL 或平台线路，并解释为什么；
7. 询问哪些信息在公开前必须隐藏。

记录完成时间、误解点、回退次数和用户主动提出的信息，不只记录主观喜好。

## 12. 进入 UI 实现前的决策

- 品牌名称和视觉不是当前阻塞，可暂用“镜序 Studio”；
- 快速创作与 Canvas 共用 Workflow Engine，但 UI 不共用同一复杂度；
- 漫剧继续使用严格阶段 Gate，不改成通用 DAG；
- 社区发布必须先做 Snapshot 和脱敏服务，不能先做 Feed 再补治理；
- 移动端首版聚焦查看、审核和社区，复杂生产留在桌面。
