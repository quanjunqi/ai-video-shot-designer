# 开发规则（不贰过）

> 本文件是从实际 bug 中提炼的强制规则。每次开发前必须阅读，每次提交前必须自检。
> 规则编号永久不变，新增规则追加编号，不修改已有编号。

## 一、UI 反模式（代码层可检测）

### R-UI-001：侧栏/窄容器标题必须 `whitespace-nowrap`
- **触发场景**：宽度 < 400px 的容器内的标题（h2/h3/label）
- **反模式**：标题因容器太窄而竖排（"项目"在上，"设置"在下）
- **修复**：所有侧栏标题加 `whitespace-nowrap`
- **检测**：`grep -rn 'h2 className=' src/features/comic/ | grep -v 'whitespace-nowrap'`

### R-UI-002：多列布局在窄栏必须降级
- **触发场景**：侧栏（< 400px）内使用 `grid-cols-3` / `grid-cols-4`
- **反模式**：控件挤压、文字截断、按钮重合
- **修复**：侧栏内最多 `grid-cols-2`，筛选控件用 `flex-wrap`
- **检测**：`grep -rn 'grid-cols-[34]' src/features/comic/`

### R-UI-003：按钮/可点击元素必须有 hover 反馈
- **触发场景**：所有 `button`、可点击 `div`、`Link`
- **反模式**：hover 无视觉变化，用户不知道可点击
- **修复**：至少加 `hover:bg-*` 或 `hover:text-*` 或 `hover:scale-*`
- **检测**：人工检查（代码扫描难以覆盖）

### R-UI-004：空状态必须有引导
- **触发场景**：列表/网格无数据时
- **反模式**：只显示"暂无数据"，用户不知道下一步做什么
- **修复**：空状态 = 图标 + 说明文字 + 行动按钮（如"创建"、"进入工坊"）

### R-UI-005：可折叠组件必须有过渡动画
- **触发场景**：所有展开/折叠组件
- **反模式**：瞬间展开/折叠，视觉跳变
- **修复**：用 `grid-rows-[0fr]→grid-rows-[1fr]` 或 `max-height` 过渡

### R-UI-006：长文本必须防溢出
- **触发场景**：卡片标题、标签、下拉选项
- **反模式**：长文本溢出容器、破坏布局
- **修复**：`truncate` 或 `break-words` 或 `line-clamp-*`

## 二、数据持久化（功能层必须验证）

### R-DATA-001：用户可修改的设置字段必须同步服务端
- **触发场景**：项目设置、用户偏好、规则配置等用户可修改的字段
- **反模式**：只写本地 localStorage，刷新/切换页面后丢失
- **修复**：修改时调用 API 同步服务端；本地为乐观更新，API 失败回滚
- **验证**：修改 → 切换页面 → 返回 → 检查数据保留

### R-DATA-002：mergeServerProject 不得覆盖本地未同步的修改
- **触发场景**：从服务端加载项目数据时
- **反模式**：直接用服务端值覆盖本地字段
- **修复**：比较 updatedAt，本地更新则保留本地值；或前端修改时立即同步服务端

### R-DATA-003：数据修改必须验证完整闭环
- **触发场景**：所有涉及数据修改的功能
- **验证步骤**：
  1. 修改后立即显示正确（不报错）
  2. 刷新页面后数据保留
  3. 切换页面后返回数据保留
  4. （如适用）多标签页一致性

## 三、CRUD 完整性（功能层必须检查）

### R-CRUD-001：列表页必须支持删除（单选/多选/全选）
- **触发场景**：所有列表页（项目、渠道、模型、协议、资产等）
- **反模式**：只有创建，没有删除入口
- **修复**：列表页必须有：单项删除按钮 + 多选 checkbox + 全选 + 批量删除

### R-CRUD-002：所有配置项必须支持编辑
- **触发场景**：渠道、模型、协议、规则等配置项
- **反模式**：只能创建不能修改
- **修复**：每个配置项必须有编辑入口，编辑后保存生效

### R-CRUD-003：敏感信息不得明文展示
- **触发场景**：API Key、令牌、密码等
- **反模式**：在列表/卡片上明文展示 API Key
- **修复**：列表上只显示掩码（如 `sk-****abcd`），编辑页有"小眼睛"切换显示

## 四、自检流程（每次提交前必须执行）

```
迭代自检 = 代码逻辑检查 + UI 视觉检查 + 数据持久化检查
```

### 4.1 代码逻辑检查
- [ ] CRUD 完整性（R-CRUD-001/002/003）
- [ ] 状态机正确性（状态迁移、边界情况）
- [ ] 数据一致性（关联数据、级联删除）
- [ ] 错误处理（API 失败、网络异常、空数据）

### 4.2 UI 视觉检查（必须浏览器截图验证）
- [ ] 文字竖排（R-UI-001）
- [ ] 窄栏挤压（R-UI-002）
- [ ] 按钮重合（人工检查）
- [ ] hover 反馈（R-UI-003）
- [ ] 空状态引导（R-UI-004）
- [ ] 折叠过渡（R-UI-005）
- [ ] 长文本溢出（R-UI-006）
- [ ] 响应式断点（md/lg/xl）

### 4.3 数据持久化检查
- [ ] 修改 → 刷新 → 读取闭环（R-DATA-003）
- [ ] 切换页面后数据保留（R-DATA-001）
- [ ] 服务端数据已同步（检查数据库或 API 返回）

## 五、React Hooks 规则（运行时错误，类型检查无法捕获）

### R-HOOK-001：useState/useEffect 等 Hooks 必须在组件顶层调用，禁止在早期 return 之后
- **触发场景**：组件中有条件渲染（`if (!data) return <Empty />`），在条件分支后新增 Hooks
- **反模式**：`if (!interp) return (...)` 之后写 `const [showNotes, setShowNotes] = useState(false)`
- **错误表现**：`Rendered more hooks than during the previous render`，页面白屏
- **修复**：所有 Hooks 必须放在组件函数体最顶层、任何早期 return 之前
- **检测**：
  ```bash
  # 检测 if (...) return 之后是否有 useState/useEffect/useMemo/useCallback
  # 人工审查：每个组件的 Hooks 是否都在第一个 return 之前
  grep -n 'useState\|useEffect\|useMemo\|useCallback' src/features/comic/*.tsx | head -20
  ```
- **工具**：项目应配置 `eslint-plugin-react-hooks`，`rules-of-hooks` 规则可在代码阶段捕获此错误

### R-HOOK-002：自迭代检必须包含浏览器渲染验证，不能只靠类型检查
- **触发场景**：任何涉及 React 组件修改的任务
- **反模式**：只运行 `tsc --noEmit` 就宣称"自检通过"
- **修复**：自迭代检清单必须包含"浏览器实际渲染验证"项，修改组件后必须在浏览器中打开对应页面确认无运行时错误
- **检测**：自检报告中必须有浏览器截图或页面文本验证记录

## 六、gate 自动化检测

在 `apps/web/package.json` 的 `gate` 脚本中添加：

```bash
# UI 反模式检测
echo "=== UI 反模式检测 ==="
# R-UI-001: 侧栏标题缺 whitespace-nowrap
grep -rn 'h2 className=' src/features/comic/ | grep -v 'whitespace-nowrap' && echo "WARN: 可能存在标题竖排" || echo "PASS"
# R-UI-002: 窄栏多列布局
grep -rn 'grid-cols-[34]' src/features/comic/ && echo "WARN: 窄栏可能存在多列挤压" || echo "PASS"
```
