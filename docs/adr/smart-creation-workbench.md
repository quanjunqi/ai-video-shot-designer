# ADR-006：智能创作（三工作台）信息架构与参数面板重设计

- **编号**：006
- **状态**：提议（待 Owner 确认 §7 的 D1/D3/D4/D8）
- **日期**：2026-10-10
- **相关**：ADR-003（模型路由层）、ADR-004（中转站与供给池）、产品设计文档 §3.4

## 1. 背景与启动条件

「智能创造三工作台 UI 重构」此前列为暂缓项：参数表单应由协议模板能力生成，否则改模型就要改前端。

启动条件核对（结论：基本满足，可以启动）：

| 要素 | 状态 |
|---|---|
| 模型能力可被前端读取（`capability` JSONB） | ✅ 已具备 |
| 能力查询端点（合并模型 + 模板能力） | ✅ 已存在 |
| 该端点前端可达（经 BFF 泛化转发） | ✅ 可达 |
| 协议模板能力声明完整度 | ⚠️ 仅 2/9，其余为空 |
| 真实执行链路 | ✅ 已打通 |
| 前端是否消费以上能力 | ❌ 完全没有 |

**设计红线**：因模板能力声明不全，「参数表单完全由能力生成」当前不可行，必须做**能力优先 + 有据可依的降级**，而不是单一数据源。

## 2. 目标

1. 参数面板由模型目录能力驱动 → 换模型/改目录不需要改前端
2. 创作者在一个页面内完成：写提示词 → 调参 → 生成 → 看结果 → 复用迭代 → 落资产
3. 三个工作台共用一套类型化组件，差异来自能力而不是三份字面量
4. 生成前可预知代价（费用、时长上限、参考图上限），生成后可复盘（元数据）
5. 视觉与交互达到 Awwwards 级品质标准

## 3. 非目标

- 不改服务边界、不新增/删除微服务
- 不修改 `capability` 现有字段语义（只做追加式扩展）
- 不重做任务中心
- 不动无限画布与漫剧工坊
- 不接真实产物落盘（依赖 MinIO 落盘项）
- 不引入新的 UI 依赖库

## 4. 设计决策

### D1 · 布局：保留「左输入 / 右结果」两栏骨架，把参数栏收敛为输入区内的胶囊

国内主流（可灵、即梦、PixVerse 等）均为左右两栏；趋势不是换骨架，而是把参数从侧栏收进输入区。

- 左栏 = composer 形态：参考图条 → 提示词输入 → 能力胶囊（`capability.modes`）→ 参数胶囊 → 模型档位选择器 → 费用预估 → 生成按钮
- 常显参数只留最高频 3–4 个，其余进「高级参数」浮层（渐进披露）
- 模型档位旁直接标注预估消耗
- 结果区以画廊/列表切换，详情用抽屉（含种子与全参数）
- 明确不做：整页对话流布局、三栏大表单

### D2 · 参数面板：能力优先 + 三级降级（最关键的决策）

数据源优先级：

1. `model.capability`（今天即可用）→ 决定哪些控件存在
2. 协议模板 `capabilities[mode]`（2/9 有声明）→ 决定控件映射到请求的哪个字段 + 提交前必填校验
3. 前端类型默认控件 schema → 仅当 1、2 都未声明时兜底

红线：
- 默认 schema 只声明控件种类与顺序，不得声明协议字段名/取值
- 模型不支持的能力不渲染控件（而不是渲染后置灰）
- 提交前用 `required_params` 做前置校验，给出字段级原因
- 条件支持（如"仅 1080P 且仅无声视频"）当前无法表达 → 记为缺口（§7 问题 8）
- 同一 schema 允许多种投影（表单 / JSON 视图）
- 费用展示：档位旁标单价 + 提交前预估 + 三色阈值，声明排队不计费

### D3 · 比例清单：目录只声明「数量」不声明「清单」

`capability.aspectRatioCount` 是数字，没有任何地方声明具体是哪些比例。

- **C（推荐过渡）**：用 `aspectRatioCount` 取通用比例清单前 N 项，并如实标注 `aspectRatioSource: 'count-fallback'`（零后端改动）
- **B（推荐终态）**：`capability` 追加 `aspectRatios: string[]`（迁移 + 后端 + 设置页，独立任务卡）
- 建议先 C 后 B，避免长期"声称支持 6 种比例、实际只有 3 个按钮"

### D4 · 结果归属：智能创作需要「个人素材」

当前 `Asset.projectId`/`episodeId` 为必填，无项目场景下结果无法进资产库。

- 本次：结果落本地结果库（含完整元数据与参数快照），UI 明确标注"尚未入库"
- 后续：asset 服务提供 `scope=personal`（workspace 级、project 可空）后提升为正式资产
- 需 Owner 决策：是否同意"个人素材（project 可空）"数据模型方向（需要 asset 迁移）

### D5 · 三页合一：一个类型化 `CreateWorkbench`

- 路由与 URL 不变（`/create/image|video|audio`）
- 页面文件只声明 `kind`，控件由 D2 的能力/模板/默认 schema 生成
- 删除三份 `params` 字面量与写死的 `unitCost`

### D6 · 状态与手感

- 草稿持久化（提示词/参数/参考图按 kind 落本地，刷新不丢）
- 提交快捷键：回车提交 + `⌘/Ctrl + Enter`；多行输入区分「Enter 提交 / Shift+Enter 换行」
- 批量提交前弹窗告知总消耗
- 轮询：有 queued/running 时 2s，无任务时停止；`document.hidden` 暂停
- 结果卡操作：下载 / 复用参数 / 作为参考图 / 生成变体 / 删除 / 取消 / 重试
- 「沿用设置（换 seed）」与「完全照抄」是两个不同按钮
- 种子是策略枚举（固定/随机/递增/微调/沿用父任务），上游未返回时如实标注
- 单条删除必须支持
- 详情抽屉：模型/渠道/全部参数/耗时/费用 + 一键回填 composer
- 失败态渲染 `ServerTask.error` 原文

### D7 · 复用平台独有资产：风格库 + 镜头语言库

- 风格库 → composer 风格预设 chips（点击把风格提示词追加/替换）
- 镜头语言库 → 视频工作台镜头语言插入
- 仅作为提示词片段插入，不得改写锁定剧本

### D8 · 音频：目录 DB 约束级缺口

`model_catalog.type` 的 CHECK 仅允许 text/image/video → 音频模型无法入库、无法执行，而产品文档要求音频首期支持。

- **A（推荐本次）**：音频工作台只做 composer 重构，卡片显式标注"音频未接入执行链路"
- **C（推荐整体）**：A + 把"音频模型类型缺失"登记为暂缓项（带启动条件）

### D9 · 品质门禁

- 结果主舞台必须有真实空态/加载态/失败态，不用假数据占位
- 交付前执行六步硬门禁，`npm run gate` 必须 GATE=0

### D10 · 队列与取消：区分状态，前置声明计费口径

专业工具的教训：取消是多模型 + 积分平台纠纷的源头，当前实现无状态区分。

- `queued` 取消 = 立即移除，永不执行，不产生费用
- `running` 取消 = 只发中断信号，UI 必须如实告知"任务可能仍会完成"
- 计费口径：排队不计费；已开始执行后取消按已运行时长计费；从未开始不计费
- 队列是可管理对象：分段展示、逐项取消、暂停/恢复、保留原参数重试
- 三种超时分离：服务端绝对截止 / 单次尝试超时 / 客户端等待

依赖缺口：计费部分依赖尚不存在的积分账本，已登记暂缓项。账本落地前 UI 只做口径声明与状态区分，不假装已退款。

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 7/9 协议模板无 capabilities | 模板级映射覆盖不全 | D2 三级降级；补齐列为独立任务 |
| 参考图以 dataURL 存本地草稿 | localStorage 体积爆掉 | 草稿只存受限张数/引用 |
| 结果仍为占位图 | 体验仍是演示 | 与 MinIO 落盘项联动 |
| 没有积分账本，D10 计费口径无法真正执行 | 用户看到"按已运行计费"却查不到明细 | 账本落地前只做口径声明，不假装已退款 |
| composer 改动大、触及 3 个路由页 | 回归风险 | 分片交付，每片独立 PR + gate |
