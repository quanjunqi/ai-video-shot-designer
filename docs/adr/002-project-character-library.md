# ADR-002: 项目级角色库作为唯一事实源

## 状态

- **状态**：已接受
- **日期**：2026-10-10
- **决策者**：项目 Owner
- **相关 ADR**：无

---

## 背景

漫剧工坊中，角色资产在多个层级出现：
- 项目级角色库（Project Character Library）
- 单集角色资产（Episode Character Assets）
- 分镜中的角色引用

面临的问题：
- 角色档案应该存在哪里？
- 单集是否需要复制角色档案？
- 如何保证跨剧集角色一致性？

约束条件：
- 一个项目可能有多集，角色在多集中出现
- 角色可能有状态变体（如受伤、换装）
- 生成图片时需要角色参考图保证一致性

---

## 决策

**我们决定：项目级角色库是角色身份的唯一事实源，单集只存引用关系和状态变体。**

具体规则：
1. 角色档案（基本信息、外貌、服装、标准立绘）存储在项目级角色库
2. 单集角色表只存储：角色引用ID、本集状态变体、本集变体立绘
3. 变体立绘使用图生图（image-to-image），基于标准立绘生成，保证角色一致性
4. 从分镜提取角色时，先匹配项目角色库，用户确认后引用，不重复创建
5. 同一角色可能有多个设定（如Q版、年轻态），用户选择引用哪个档案

---

## 备选方案

### 方案 A：单集独立存储角色档案

**描述**：每个剧集独立存储完整的角色档案，剧集之间不共享。

**优点**：
- 简单直接，无跨集依赖
- 每集可以独立修改角色

**缺点**：
- 数据冗余，同一角色在多集重复存储
- 角色一致性难以保证，各集可能描述不一致
- 修改角色需要同步多集，容易遗漏
- 标准立绘需要重复生成，浪费算力

**结论**：不选，因为数据冗余且一致性差。

### 方案 B：全局角色库（跨项目共享）

**描述**：建立全局角色库，所有项目共享角色档案。

**优点**：
- 角色资产可跨项目复用
- 集中管理角色

**缺点**：
- 不同项目的角色可能同名但设定不同
- 权限管理复杂（哪些角色可见/可用）
- 项目独立性被破坏
- 当前阶段不需要跨项目共享

**结论**：不选，因为过度设计，当前阶段不需要。

---

## 决策理由

1. **单一事实源**：角色身份只有一个来源，避免数据不一致
2. **引用而非复制**：单集通过引用关联角色，修改角色档案自动同步所有剧集
3. **变体分离**：标准立绘在项目级，状态变体在单集级，职责清晰
4. **图生图保证一致性**：变体立绘基于标准立绘生成，角色外观一致
5. **用户确认机制**：从分镜提取角色时先匹配项目库，用户确认后引用，避免误创建

---

## 后果

### 正面影响

- 角色数据不冗余，存储高效
- 跨剧集角色一致性有保障
- 修改角色档案一次生效，无需同步多集
- 标准立绘只生成一次，节省算力
- 角色资产管理集中，便于维护

### 负面影响

- 需要处理引用关系，数据模型稍复杂
- 删除角色需要检查引用关系
- 单集角色详情需要关联查询项目角色库
