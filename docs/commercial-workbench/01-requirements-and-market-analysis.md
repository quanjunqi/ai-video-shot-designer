# 需求与市场分析

## 1. 产品机会

AIGC 用户面对的不是单一生成问题，而是三种不同任务：

- 我现在只想快速生成几张图片或几段视频；
- 我想把多个步骤保存成可以重复运行、批量处理和分享的方法；
- 我正在制作一部漫剧，需要剧本、资产、分镜、生成和审核的完整生产空间。

现有产品常见问题是把三种任务混在一个节点画布中，或者把所有用户都引导到某个行业流程。结果是简单任务被复杂化，复杂生产又缺少版本、审核和领域约束。

镜序 Studio 的机会是：以统一模型与算力底座承载三种创作方式，让用户根据任务自由切换，而不是根据所谓用户等级选择产品。

## 2. 产品结构

| 创作方式 | 用户要完成的事 | 产品形态 |
|---|---|---|
| 快速创作 | 生成图片或视频 | 直接生成工作台 |
| 工作流编排 | 固化并重复一套生成方法 | 步骤、批量、画布和简化表单多视图 |
| 漫剧工作台 | 完成一部漫剧的专业生产 | 阶段 Gate、Shot / Unit / Take 和审核 |

共享能力：项目、资产、任务、模型、API、本地 ComfyUI、云端算力、费用、权限、社区和 Agent。

## 3. 为什么模型与算力应先建设

创作工作台的质量取决于底层是否能稳定回答五个问题：

1. 当前任务需要什么 Capability；
2. 哪些模型满足输入输出和质量约束；
3. API、本地 ComfyUI、云 GPU 哪条线路可用；
4. 预计费用、等待时间、隐私和复现条件是什么；
5. 失败、取消、重试和结果入库是否可靠。

如果每个工作台分别调用供应商，模型切换、成本、错误、资产和审计会迅速失控。因此模型能力中心和执行中心是平台第一优先级。

## 4. 目标用户与使用情境

产品不以用户水平划分权限，但仍需理解不同情境：

| 情境 | 典型目标 | 首选方式 |
|---|---|---|
| 临时创意 | 快速尝试 4 张图或 2 段视频 | 快速创作 |
| 重复内容生产 | 固定步骤、替换素材、批量运行 | 工作流步骤/批量视图 |
| 复杂依赖排查 | 理解分支、合并和中间结果 | 工作流画布视图 |
| 使用成熟方法 | 只填写输入并运行 | 模板简化表单 |
| 漫剧生产 | 管理角色、镜头、连续性和审核 | 漫剧工作台 |
| 分享方法 | 发布作品及可复现过程 | 社区发布快照 |

同一用户可以在一天内经历全部情境，产品不应强迫其切换身份或套餐心智。

## 5. 核心用户任务

| 当……时 | 用户希望 | 产品必须提供 |
|---|---|---|
| 想快速验证画面 | 输入 Prompt 后立即生成 | 默认参数、模型/线路推荐、报价和结果网格 |
| 有首帧并想生成视频 | 清楚模型限制与费用 | 参考资产、时长/比例、候选和长任务管理 |
| 重复同一套做法 | 保存步骤并替换输入 | WorkflowVersion、变量、单步运行和缓存 |
| 批量尝试 Prompt | 看到每一行结果与费用 | 表格变量、批量报价和局部重试 |
| 流程存在分支 | 看清依赖和错误路径 | 可选画布、自动布局和检查器 |
| 使用本机模型 | 不暴露公网 ComfyUI | Local Agent 主动连接和依赖预检 |
| 使用云 GPU | 不关心实例运维细节 | 镜像、缓存、调度、扩缩容和成本上限 |
| 制作漫剧 | 稳定交付大量连续镜头 | 专业阶段、资产、Shot/Unit/Take 和审核 |
| 分享作品与方法 | 他人可以正确复现 | 不可变发布快照、依赖清单和 Remix |

## 6. 工作流产品判断

### 6.1 用户需要的是编排，不一定是无限画布

无限画布适合表达非线性拓扑，但也带来缩放、连线、布局、参数查找和移动端适配成本。大量实际工作流是线性的，或者只有一个并行组，步骤列表通常更高效。

因此采用“一个工作流模型，多种视图”：

- 步骤视图作为默认；
- 批量视图处理变量矩阵；
- 画布视图处理复杂拓扑；
- 简化表单用于直接运行成熟模板。

### 6.2 需要验证的问题

- 用户创建的真实工作流有多少存在复杂分支；
- 步骤视图是否足以完成首次创建和日常维护；
- 画布在排错时的价值是否高于编辑时；
- 批量任务是否主要发生在表格中；
- 模板使用者是否根本不需要看流程结构。

在数据形成前，不把“无限画布”作为产品定位或主导航名称。

## 7. 三类执行线路需求

### API

优势是即开即用、无需部署；风险是单价、限流、模型变更和供应商依赖。产品需要统一 Adapter、错误、Webhook、价格和用量。

### 本地 ComfyUI

优势是隐私、已有模型资产和低增量成本；风险是环境差异、节点依赖、设备离线和资源不足。产品需要安全 Local Agent，而不是让用户暴露端口。

### 云端算力

优势是模型自由度和批量能力；风险是冷启动、GPU 闲置、镜像/模型分发和运维成本。产品需要标准 Runner、Fleet、Scheduler 和自动回收。

三条线路不是三个独立功能，而是同一 Capability 的可替代执行方式。

## 8. 漫剧的差异化价值

通用工作流不能自然表达漫剧的专业事实：

- 剧本是否锁定和完整覆盖；
- 角色、服装、场景和道具的 canonical 版本；
- 场景空间、走位、屏幕方向和机位；
- Shot 与模型执行 Unit 的差异；
- 多 Take 审核、采纳和实际尾帧；
- 上游修改导致哪些下游 stale。

现有 Shot Designer 已形成这些规则，是第一个专业工作台的核心，不应退化成一组通用节点。

## 9. 社区需求

社区不只是作品 Feed。高价值内容是：

```text
作品结果 + 创作参数/WorkflowVersion + 模型与线路兼容性
+ 可公开资产 + 成本和复现条件 + 作者与来源
```

Remix 必须创建新项目并冻结来源版本。社区不能公开 Secret、本地路径、内网地址和私有资产。

## 10. 优先级

### P0：平台生产主干

- Workspace、权限、Secret 和审计；
- Capability、Model、Adapter 和三类 Execution Route；
- Job、WorkflowRun、Asset、Usage 和 Billing；
- 图片/视频快速生成；
- Local ComfyUI Agent；
- Cloud Runner 与基础调度；
- Workflow 步骤视图和批量运行；
- 漫剧 Shot / Unit / Take 黄金路径。

### P1：完整产品闭环

- 可选画布视图；
- 模板简化表单；
- 漫剧完整阶段、团队审核和交付；
- 社区快照、Remix 和治理；
- 路由质量/价格策略和成本分析。

### P2：生态扩展

- 第三方 Adapter/节点 SDK；
- 工作流商业交易和分成；
- 更多专业工作台；
- 企业私有化、SSO 和专属集群；
- 外部内容平台数据连接器。

## 11. 当前明确不做

- 不接入 `depth-video-converter` 及其任何能力；
- 不把视频后期工具作为平台主干；
- 不做完整 NLE；
- 不用“爆款评分”制造确定性；
- 不开放任意第三方代码在公共 Runner 执行；
- 不在可靠任务、计量和权限完成前快速堆模型数量。

## 12. 商业模式假设

建议采用订阅 + 用量：

- Free：有限生成、自带 API、本地 ComfyUI 和社区浏览；
- Pro：更多项目/资产、工作流、批量运行和云端算力；
- Team：成员、漫剧、审核、预算和审计；
- Enterprise：SSO、私有化、专属 Runner 和 SLA。

套餐名称不映射用户能力等级；功能差异来自资源、协作、治理和服务保障。

## 13. 成功指标

北极星指标：每周被下载、发布或正式采纳的有效生成结果数。

关键指标：

- 首次图片/视频结果的中位时间；
- 成功生成后继续编辑或复用的比例；
- 工作流第二次运行率和批量完成率；
- 步骤/批量/画布各视图的真实使用占比；
- API、本地 ComfyUI、云 GPU 的成功率和有效结果成本；
- Local Agent 连接成功率和断线恢复率；
- 云 GPU 利用率、冷启动时间和闲置成本；
- 漫剧 Take 采纳率和一致性返工率；
- Publication Remix 成功率；
- 四周留存、付费转化和贡献毛利。

## 14. 需求结论

产品核心不是四个并列频道，而是一套共享生产系统：简单生成不被复杂化，重复方法可以工作流化，漫剧生产保留专业约束。模型与三类算力线路是所有体验的底座，工作流画布只是可选交互，不是产品目的。
