# 迭代自检复盘（2026-09-29）

## 事件经过

用户要求对「今天所有修改项」进行迭代自检。完成 A/B/C 三层代码逻辑扫描后，宣称「迭代自检已全部完成，12 项问题中 11 项已修复」。

用户随即上传截图，指出项目详情页右侧栏存在严重 UI 布局问题：
- 「项目设置」标题竖排（"项目"在上，"设置"在下）
- 「项目资产库」标题竖排
- 筛选控件挤压在一行
- 5 个参数单列排列，松散占空间
- 空模型下拉框无占位提示

用户质疑：「这种 UI 布局，也认为是迭代自检已全部完成吗？」

## 根因分析

### 1. 自检范围缺失：只做了代码逻辑层，完全漏掉 UI 视觉层

本次自检的三层划分：
- A 层（剧集生命周期）：检查 CRUD、状态机、数据一致性、span 计算
- B 层（设置中心）：检查 CRUD 入口完整性、类型分类
- C 层（工坊流程）：检查阶段定义、导航、Gate 逻辑

**全部是代码逻辑检查，没有一项是浏览器截图视觉检查。** 代码逻辑正确不代表 UI 布局正确——`whitespace-nowrap` 没加、`grid-cols-4` 在 300px 窄栏下挤压，这些在代码扫描中完全发现不了。

### 2. 「自检完成」的判定标准过低

宣称「自检完成」的依据是：
- gate 0 error/0 warning
- 代码扫描没有发现逻辑 bug
- 浏览器实测了数据路径（插入/删除/解锁）

**但没有验证：**
- 页面在真实浏览器中的视觉效果
- 文字是否竖排/溢出
- 按钮是否重合
- 窄栏/宽栏的响应式表现
- 空状态的可读性

### 3. 数据持久化未验证

用户随后发现第二个问题：项目设置参数（画面比例、默认模型等）修改后刷新丢失。

根因：`updateProject` 只写本地 zustand（persist 到 localStorage），没有同步服务端；`mergeServerProject` 直接用服务端值覆盖设置字段，本地修改被丢弃。

这个问题在自检中完全没有发现——因为自检只验证了「修改不报错」，没有验证「修改后刷新是否保留」。

## 教训总结

### 教训 1：代码逻辑通过 ≠ 自检完成

UI 修改的自检必须包含**浏览器截图视觉检查**。代码扫描只能发现逻辑 bug，发现不了布局 bug。

### 教训 2：建立强制 UI 自检清单

每次涉及 UI 的修改，自检必须逐项检查：

| 检查项 | 说明 | 验证方式 |
|---|---|---|
| 文字竖排 | 标题/标签是否因容器太窄而竖排 | 浏览器截图 |
| 文字溢出 | 长文本是否溢出容器 | 浏览器截图 + 窄屏测试 |
| 按钮重合 | 相邻按钮/控件是否重叠 | 浏览器截图 |
| 窄栏挤压 | 侧栏/窄容器内的多列布局是否挤压 | 浏览器截图 + 容器宽度检查 |
| 响应式断点 | md/lg/xl 断点切换是否正常 | 多宽度截图 |
| 空状态 | 无数据时的占位/引导是否清晰可读 | 浏览器截图 |
| 折叠/展开 | 可折叠组件的过渡动画是否正常 | 浏览器交互 |
| hover 状态 | 可交互元素的 hover 反馈是否明显 | 浏览器交互 |

### 教训 3：数据修改必须验证刷新持久化

每次涉及数据修改的功能，自检必须验证：
1. 修改后立即显示正确（不报错）
2. **刷新页面后数据保留**（持久化）
3. **后退/重新进入后数据保留**（路由切换）
4. 多设备/多标签页一致性（如果适用）

### 教训 4：「不报错」不等于「功能正常」

项目设置修改不报错，但刷新后丢失——这是「静默失败」。自检不能只看有没有报错，还要看功能的完整闭环（修改 → 保存 → 刷新 → 读取）。

### 教训 5：Awwwards 级标准需要主动追求，不是被动达标

用户给的标准是「以 Awwwards、Webby Awards、FWA 获奖级网站为品质标准」。这意味着：
- 不能满足于「能用」，要追求「精致」
- 不能只修 bug，要主动优化视觉层级、动效、微交互
- 每个组件都要从八个维度（排版、留白、视觉层级、色彩、动效、微交互、响应式、原创性）自检

## 后续待办

1. **后端 PATCH /projects/{id} API**：当前前端设置修改只持久化到 localStorage，刷新后靠 updatedAt 比较保留。需要后端 API 支持真正的服务端持久化。
2. **window.confirm 统一为 AlertDialog**：渠道删除确认仍用原生 confirm，与项目其他地方风格不一致。
3. **UI 自检清单纳入开发流程**：每次 UI 修改后必须按清单逐项截图验证，不能只靠代码扫描。
4. **数据持久化闭环测试**：每次数据修改功能必须验证「修改 → 刷新 → 读取」完整闭环。

## 自检方法论更新

从本次复盘开始，迭代自检的标准更新为：

```
迭代自检 = 代码逻辑检查 + UI 视觉检查 + 数据持久化检查
```

- **代码逻辑检查**：CRUD 完整性、状态机正确性、数据一致性、边界情况
- **UI 视觉检查**：强制清单逐项截图验证（见教训 2）
- **数据持久化检查**：修改 → 刷新 → 读取完整闭环验证

三项全部通过，才能宣称「自检完成」。
